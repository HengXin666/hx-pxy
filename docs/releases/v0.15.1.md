# HX-Pxy v0.15.1

## 修复

- **控制面读不到本机网桥**：生产 unit 的 `RestrictAddressFamilies` 少了 `AF_NETLINK`。Go 通过
  NETLINK_ROUTE 读接口表，缺这个地址族时 `net.Interfaces()` 直接失败，控制面看到 0 个接口，
  于是宿主上明明有 `docker0` 和多个 compose `br-*`，弹窗仍然说“本机未检测到 Docker 网桥”。
  现在控制面 unit 放行 `AF_NETLINK`（数据面的 TUN drop-in 早就为同一原因放行过），
  Docker 网桥 / LAN 发现、网络诊断和 Docker 入口编译恢复正常。
- **不再把“读不到”说成“不存在”**：`DiscoverBridges()` 改为返回错误而不是空列表，判定层新增
  `reason=bridge_scan_failed`。只有真正读过接口表才允许说 `no_docker_bridge`；读不到时弹窗直说
  “控制面读不到本机网络接口列表（systemd 沙箱缺少 AF_NETLINK，或控制面在容器网络命名空间里），
  请检查部署配置，而不是 Docker 是否在运行”。已有网桥入口也不会再被误判成 `entry_unreachable`。

## 验证

- 真实二进制 + 真实沙箱 before/after：`RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6` 下
  `state=blocked reason=bridge_scan_failed bridges=0`；加上 `AF_NETLINK` 后
  `state=needs_entry reason=loopback_bind bridges=10 gateway=172.17.0.1 plan=yes`（宿主 10 个网桥）。
- `go test -count=1 ./...`（36 个包）与 `go vet ./...` 通过；新增扫描失败路径的单元与 service 测试、
  控制面 unit 的 `AF_NETLINK` 契约断言。
- 前端类型检查、生产构建和 18 项运行时逻辑测试通过；Agent Notes 门禁通过。

## 升级与边界

执行 `sudo hx-pxy-install upgrade`。升级会重新安装 `deploy/systemd/hx-pxy.service` 并
daemon-reload、重启控制面，无需手工改 unit；数据库、主密钥和认证器绑定不变。

控制面能看到网桥地址只代表候选地址存在：容器网络、宿主防火墙和 rootless Docker 仍需现场验证，
弹窗给出的连通性结论不替代实际拨测。
