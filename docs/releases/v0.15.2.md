# HX-Pxy v0.15.2

## 修复

- **共享入口用户名冲突提前到写库前拒绝**：`standard` 族的所有 HTTP / SOCKS / Mixed 成员共用
  7890 上的同一个 Mixed listener，靠 `IN-USER` 按用户名分流，因此同一族内用户名必须唯一。
  此前这条不变量只在编译期成立：写库路径不检查，前端新建表单又把用户名默认成固定的
  `hx-user`，所以第一个用默认值建的服务成功，之后任何不改用户名的表单新建都会写入行、
  整份配置编译失败、回滚，并对外报成 `502 dataplane_apply_failed`。
  `listener.Create` / `Update` 现在按 carrier family 查重，判据与编译器一致（只比较已启用成员、
  已启用组、按 `SharedInboundCarrierKey` 分族、用户名 `TrimSpace` 后比较、更新时排除自身），
  命中返回 `409 shared_inbound_username_taken` 并在消息里点名占用者与族。
- **新建代理服务默认用户名每次唯一**：表单默认值改为 `hx-<8 位随机>`，与同表单的密码默认值
  一致；用户仍可改成自己想要的名字。编译器里的重复检查保留，它仍是迁移直接写库和绕过
  listener service 的写入的最终边界。

## 验证

- 隔离实例实机 smoke（独立数据库、临时端口）：第一次创建用户名 `hx-user` 返回 `201`，
  第二次同用户名返回 `409 shared_inbound_username_taken`，库里只留下第一个 listener，
  无回滚残留，数据面编译通过。
- `go test ./...`：791 passed / 37 packages；`go vet ./...` 通过。
- 前端类型检查、生产构建、18 项运行时逻辑测试通过；Agent Notes 门禁（tree / format /
  backlinks / archive / coverage）通过。

## 升级与边界

执行 `sudo hx-pxy-install upgrade`。

本次修复只阻止**新的**冲突：如果某个安装的库里已经存在同族重名（历史数据），重启后编译仍会
拒绝整份配置，需要把其中一个服务改成别的用户名。已发布订阅里的用户名不会被自动改写。

`409 shared_inbound_username_taken` 直接出现在 `POST/PUT /api/v1/listeners`；
`POST /api/v1/proxy-services` 仍按其既有契约返回 `422 proxy_service_create_failed`，
但消息里包含完整原因。
