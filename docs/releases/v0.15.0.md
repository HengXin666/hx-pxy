# HX-Pxy v0.15.0

## 新增

- **Docker 连接评估与一键入口**：环回、无凭据和 WebSocket 服务不再直接拒绝。服务端评估返回
  `ready` / `needs_entry` / `client_landing` / `blocked`；`needs_entry` 会预览一个使用来源出口和
  生成凭据的伴随 Mixed 入口，落在可达的共享 Mixed 入口，或恰好一个 Docker 网桥网关
  （不使用 `0.0.0.0`）。应用需要确认和预览的 plan id，`DELETE` 撤销。链接存于
  `docker_access_entries`（迁移 40），共享入口迁移器不接管伴随条目。
- **代理组 Retain**：在 `Sort` 与 `Limit` 之间新增可选阶段
  （`source_spec.retain = {margin, min_dwell_seconds}`，仅订阅来源且 `limit > 0` 的组）。
  仍通过全部谓词且未隔离的旧成员保留席位；新成员必须领先超过 `margin`，且在位成员已过
  `min_dwell_seconds`。成员记录存于 `group_members`（迁移 41），只在 Mihomo 接受配置后写入。
- **代理组类型**：`GET /api/v1/proxy-groups` 为每个组标注 `type`
  （`residential` / `subscription` / `custom`），支持 `?type=` 逗号分隔筛选，未知值返回 422。
- **OpenAPI 契约**：新增两份 OpenAPI 3.1 文档，订阅服务与住宅渠道分开 ——
  `docs/openapi/subscription-consumer.openapi.yaml`（`/nodes` + `/sub`，只读导出）与
  `docs/openapi/residential-control.openapi.yaml`（`/ctl`，租约、轮换、CAS 守卫）。
  测试逐 schema 对照 Go 响应类型，并断言两份文档都不暴露对方的路径。

## 修复

- **订阅刷新不再退场住宅节点**：退场清扫按 `origin` 分流。`origin = 'residential'` 的节点由住宅
  渠道的分配路径自己 materialize，从不进 `subscription_nodes`；此前每次订阅刷新都会把它退场，
  组被重新发布成 `REJECT`，消费者直到下一次轮换都拿不到出口（2026-10-15 gh-pool 事故，空窗约
  10 分钟）。三处重复的清扫 SQL 收敛为 `retireDisappearedNodesSQL`，判据只有一处。
- Docker 入口：共享入口关闭时共享成员不可拨号；网桥消失的伴随条目报 `entry_unreachable`；
  来源被禁用时其伴随条目仍可撤销；`no_free_port` 单独上报；`DiscoverLAN` 跳过 `0.0.0.0`；
  端口探测同时检查 UDP；来源被禁用或其网桥地址消失的伴随条目在编译阶段被拦截，
  单个过期条目不再阻塞整次 apply。
- 通过 API 删除来源 Listener 时，服务端同时撤销其 Docker 入口；Listener 列表用
  `docker_access_for` 标记伴随条目。
- Retain：按桶上限在 Retain 内部强制，`min_dwell_seconds` 溢出安全校验，线性 challenger
  扫描，id 规范化后再校验；成员记录覆盖显式 `node_ids`，写入失败的成员关系保留为下一次基线。

## 升级与边界

执行 `sudo hx-pxy-install upgrade` 升级。数据库迁移 40（Docker 入口）与 41（组成员）自动执行，
保留现有数据库、主密钥和认证器绑定。

Retain 默认关闭：只有显式写入 `source_spec.retain` 的组才保留席位，未开启的组行为与 v0.14.1
一致。Docker 地址是连接候选值，不代表已自动修改宿主机防火墙、容器网络或 NAT；隔离网桥、
rootless Docker、环回监听仍可能阻止直连，公网可达性取决于共享入口的部署配置。
