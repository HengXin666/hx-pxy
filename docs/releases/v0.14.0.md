# HX-Pxy v0.14.0

## 加载与交互

- 代理服务行不再等待完整节点健康样本；精简节点投影、分页最多 4 路并发。
- 六类常用列表采用 5 秒、128 条上限的会话内缓存；写操作、认证变化及主动刷新失效。
- 终端心跳容忍短时中断，大粘贴分帧，断线不向新 shell 重放输入。
- Docker 列表自行滚动；手机端服务名称不再被徽章挤没。
- 新建服务可选择住宅代理频道并跳转配置供应商凭据；复用已有组，发布失败只清理新入口。
- Docker 复制使用宿主网桥/绑定地址，不退回公网域名；环回和 WS/TLS 入口明确拒绝转换。

## 可选网络运维

- TUN 默认关闭，选择代理组后由 Mihomo 接管当前环境公网流量；保留站点规则优先级。
- 提供显式安装的数据面 systemd 权限 drop-in；不会随升级自动授予网络管理权限。
- 探测当前接口/TUN，支持宿主和容器 DNS/路由诊断；确认与认证后可开关运行态 IPv4 转发。
- 活跃连接上限 500 条，标记本机 / Docker / 外网，附采样时间，不落连接历史数据库。
- Mihomo 子进程与 systemd 服务清除本地代理环境变量。

## 日志与升级注意

- 文件日志默认保留 30 天，每日清理；按大小/年龄轮转，保护活跃路径和活跃 socket。
- 生产使用独立 journald namespace，保留 30 天并设置容量上限。**systemd 要求 >=245**。
  查询命令：`journalctl --namespace=hx-pxy -u hx-pxy`。
- 不清理旧的共享 journal，以免删除其他服务记录。文件保留设置不修改 journald 策略。
- 住宅复用入口使用频道出口池；专属 sticky client 身份仍在住宅频道管理。

## 已验证与边界

Go 单元/集成测试、vet、网络/metrics/日志/API race 检查，前端类型检查与生产构建，
16 项前端逻辑测试，Docker 四视口与网络/代理服务桌面及手机浏览器回归。
TUN 配置通过真实 Mihomo 语法校验；未在开发宿主执行特权路由接管或 Docker 转发修改。

其他 TUN 的内核路由捕获不能靠清除环境变量绕过，需要宿主策略排除专用服务 UID。
Docker 修复限定 IPv4 转发，不是全自动防火墙修复；NAT/host 网络可能隐藏连接真实来源。
特权 TUN 实际出站、真实部署修复和长期弱网终端效果仍需目标环境验收。
详细权限、验证和回退说明：[网络运维](../NETWORK_OPERATIONS.md)。
