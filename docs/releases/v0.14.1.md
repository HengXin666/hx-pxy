# HX-Pxy v0.14.1

## 修复

- Docker 使用地址改为完整的带认证代理 URI，使用实际共享入口端口和宿主机网桥 / LAN 地址，不把 `0.0.0.0` 当作连接目标。共享入口按认证用户名选择出口。
- 浏览器拒绝剪贴板权限或通过非安全 HTTP 访问时，仍显示可选中、可手动复制的连接信息，不再只有复制失败提示。
- VLESS / VMess / Trojan WS 入口提供订阅和 Mihomo 客户端落地说明，不再尝试将 WS 入口转换成不可用的 `HTTP_PROXY` 地址。
- 修复品牌更名导致旧版 2FA 密文无法解密、终端验证码提交提示 `operation failed` 的问题。同一主密钥下兼容两种已发布的加密上下文，无需重绑认证器；错误验证码、错误密钥和篡改密文仍拒绝访问。
- 全局设置、服务创建和服务编辑中的代理入口端口全部只读，保留部署配置的固定端口。WS 使用固定公网入口与 URL Path，HTTP / SOCKS 使用认证用户名分流；SMTP 和住宅供应商上游网关端口不是代理入口，不受此限制。

## 验证

- `go test -count=1 ./...`、`go vet ./...` 全部通过；本地真实 Mihomo v1.19.30 覆盖共享 HTTP / SOCKS / Mixed 认证和路由，发布流水线使用固定 v1.19.29。
- 覆盖旧版 2FA 密文的启用、校验、禁用和失败路径，并通过 HTTP 2FA 校验后连接真实终端 PTY WebSocket。
- 前端类型检查、生产构建及 17 项运行时逻辑测试通过。
- 1440px / 390px 浏览器回归覆盖完整认证 URI、剪贴板拒绝、实际共享端口、只读端口和 WS 使用说明；另通过真实后端 UI 冒烟测试。
- Agent Notes 门禁和 Git diff 检查通过；页面截图保存于 `docs/screenshots/`。

## 升级与边界

执行 `sudo hx-pxy-install upgrade` 升级。保留现有数据库、主密钥和认证器绑定；不要为此重置 2FA。

Docker 地址是连接候选值，不代表已自动修改宿主机防火墙、容器网络或 NAT。隔离网桥、rootless Docker、环回监听仍可能阻止直连；本次未在目标生产环境验证这些网络条件。WS 订阅必须先由客户端内核落地，不能直接作为普通 HTTP 代理。

详细说明见 [网络运维](../NETWORK_OPERATIONS.md)。
