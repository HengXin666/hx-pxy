# Agent Note: 消费方看板 —— 一块 token 寻址的免登录固定看板

Status: implemented

Archived: 2026-09-26

## Problem

「接入 AI」页给消费者的是一段**复制出去的文案**。它的价值是让 AI 知道接口形状，
但形状不是内容：节点每天在变，而文案在粘贴的那一刻就冻结了。用户的原话是
「目前提供的前端那个 ai 复制粘贴不行。我希望直接接入固定的控件看板，能看到实时流量
+ 所有的 routing 页面的内容，并且可以选择具体的代理组和节点（可以配置是轮询还是什么的，
也支持住宅代理相关的）」。他要的是**一条活的、可吊销的、有范围限制的链接**，
而且前端要有一块统一看板、后端要有与之对接的服务。

真正的缺口有三个，都不在文案层：

1. 控制面**没有任何读接口**能给出数据面的**运行态**。`/api/v1/proxy-groups` 是 Desired
   State（SQLite 里存了什么），而「这个组现在走的哪个成员」只存在于运行中的 Mihomo 进程里。
   `select` 组的固定成员在进程内存中，重编译都读不回来。
2. 实时流量只有 `/api/v1/overview/stream`，而它在**管理员会话**后面。看板的持有者
   从来没有管理员账号。
3. 节点选择能力（`Manager.SelectProxy`）**已经存在**，但唯一调用方是住宅轮换。
   控制面自己也没有「切一个组」的管理端入口。

## Decision

**1. 新的公开面是 `/board/<token>`，与 `/sub/`、`/nodes/`、`/ctl/` 同族。**
路径段即凭据，不走 Session。它**不能**放在 `/api/v1/` 下：那是会话认证的管理域，
而 `net/http` 的 `ServeMux` 对重复注册直接 panic。

三个端点，各自对应一种节奏：

- `GET /board/<token>` —— 完整快照，一次拿全（组、成员、节点、订阅、轮换游标）；
- `GET /board/<token>/stream` —— 实时流量 SSE；
- `POST /board/<token>/switch` —— 固定一个 `select` 组的成员。

**2. 拓扑走轮询，流量走 SSE，不合成一条通道。**
一秒一个采样点用五秒轮询去取毫无意义；反过来，为了两个整数每秒重新序列化几十个组、
上百个节点同样浪费。两条通道的成本各自匹配它的变化速度。

**3. 只有 `select` 组可切换，且这一点由响应如实表达。**
`url-test` / `fallback` / `load-balance` 的成员由数据面按健康与延迟**自己重算**，
固定会被立即覆盖。所以 `groups[].switchable` 仅在 `runtime_type == "Selector"` 时为 true，
UI 据此决定是否给出切换控件，并在不能切时**说明原因**而不是静默隐藏。
契约里同时给出 Mihomo 的 `runtime_type` 和本项目的 `strategy`——
只有前者能解释「为什么这个组不能切」。

**4. 轮询是本仓库第一个挂到数据面的常驻写任务，因此门槛设得很硬。**
`rotation_strategy` 默认 `off`；间隔下限 60 秒；`DIRECT`/`REJECT`/`GLOBAL`/`COMPATIBLE`/
`PASS` 永不进候选；游标持久化（重启不跳回第一个成员）；一次只推进范围内的**第一个**
可切换组。实现是控制 socket 写入，不重编译、不重启、不影响其它组——这正是它便宜到
能当看板功能的原因。

**5. 读快照不因数据面离线而失败。**
`data_plane.running = false` + 稳定 `error_code`，同时仍列出控制面已知的组。
否则嵌在别人页面里的看板会变成空白 iframe，运维也分不清「没配」和「挂了」。

**5.1 入口收进「关于」页的顶部 tab，不占侧边栏。**
用户明确要求：「一个 ai 接入搞 2 个侧边栏？我不是让你放到关于的顶部 tab 搞吗？」
「消费方看板」与「接入 AI」都是**低频的接入配置动作**，不是日常运维页面；各占一个
侧边栏图标会把主流程（总览 / 订阅 / 代理服务）淹掉。现在关于页顶部是三个 tab
（关于 / 消费方看板 / 接入 AI），两个子页通过 `embedded` 参数隐藏自己的 h1 ——
tab 已经说明了这是哪一页，再放一个标题会与 tab 抢层级。

**5.2 终端页的容器类必须与它的滚动子页配套。**
用户报「docker 页面无法滚动、无法看到端口映射」。根因不在 Docker 页本身，而在
App 的 `main`：它在终端页同时带 `lg:h-full lg:overflow-hidden` **和** `px/py` padding。
子页的 `h-full` 因此超出可用高度，溢出部分被 `overflow-hidden` 直接裁掉，而且
**没有任何元素成为滚动容器** —— 表现就是「看不到也滚不动」。

修法是两半：`main` 在终端页不再提供 padding（交给 TerminalPage 自己承担），
两个子页用 `flex-1 min-h-0 overflow-y-auto` 而不是 `h-full`。
端口列同时去掉了 `truncate`：`docker ps` 的端口串常有六七个映射，省略号会把
`0.0.0.0:28340->8000/tcp, [::]:28340…` 截成读不出后半截，现在每条映射各占一行。

**5.3 所有自写弹窗必须走 Portal —— `.page-enter` 会让 fixed 退化。**
用户报「打开添加，弹窗显示在内部 div 里，什么都看不全」。根因是一个**跨页面的
CSS 陷阱**，不在弹窗代码本身：

`web/src/index.css` 的 `.page-enter { animation: page-in 180ms ease-out both; }` 用了
`fill-mode: both`，它会**永久保留**结束帧的 `transform: translateY(0)`。计算值是
`matrix(1,0,0,1,0,0)` 而**不是 `none`** —— 而 transform 非 none 的元素会成为
`position: fixed` 后代的**包含块**。

实测证据（Playwright，1280×800 视口）：`.page-enter` 的实际盒子是
`top:28 left:260 988×278`；写在它内部的自写遮罩 `fixed inset-0` 拿到的不是
1280×800 视口，而是**同样那一小块 988×278**，弹窗面板 `top` 直接跑到 `-103`。

三条修法，都必须做：

1. **自写遮罩改用 `createPortal(..., document.body)`**（boards-page、confirm-dialog、
   cf-account-group 三处）。Radix 的 `DialogContent` 自带 Portal，所以用它的页面不受影响 ——
   这就是为什么只有部分弹窗出问题。
2. **居中用 `grid min-h-full place-items-center` 而不是 `flex items-center`**。flex 居中时
   子项比容器高，顶部会被推出视口且**滚不回来**（实测 mobile 上 panel top = -65）；
   grid 的 center 在溢出时退化为 start，上下都可滚。
3. **滚动容器是遮罩本身**（`overflow-y-auto`），不是弹窗面板。

`web/e2e/board-dialog.mjs` 把这三条固化成四档视口的门禁，断言遮罩铺满视口、
弹窗顶部不被裁、名称输入框可见、滚到底后提交按钮可达。

**6. 前面板用 hash 路由（`#/board/<token>`）复用同一份静态产物。**
看板路由在 **authGate 之前**分流：消费者没有管理员账号，把公开面放进认证闸门会让一条
完全有效的链接死在登录页前面。

**7. 管理面（`/api/v1/boards`）是会话认证的独立资源。**
看板可创建、改范围、停用、换令牌、删除。`allow_switch` 与读范围**分开存**：
读拓扑无害，而切换会改所有人的出口。

## Alternatives considered

- **什么都不做，继续改进「接入 AI」文案。** 文案锁的是形状不是内容，节点每天在变；
  用户已明确否决这一层。否决。
- **让看板复用 `/api/v1/overview/stream` 与现有管理 API，前端带管理员 Cookie。**
  最省事，但等于把一块要发给第三方的链接绑定在管理员会话上：要么把管理员凭据交出去，
  要么看板对消费者根本打不开。这与「消费者没有账号」这一事实直接冲突。否决。
- **只发一个「只读」看板，不做节点切换。** 隔离性最好，但用户明确要求「可以选择具体的
  代理组和节点」。切换本身不重编译、不影响其它组，代价可控；因此保留为**默认关闭的**
  能力，而不是删掉。否决纯只读。
- **让轮询服务端定时轮换整块看板的所有组。** 一块看板可能有多个出口，全轮换会毁掉
  「多条出口路径」的意义；而且每次轮换都是一次数据面写。否决，改为只推进第一个可切换组。
- **把轮换做成 Mihomo 的 `load-balance` 策略，而不是控制面定时器。** 那样就不需要
  常驻写任务，看起来更「原生」。但它无法表达「每 N 秒换一个出口」——`load-balance`
  是按连接/会话分配，语义完全不同，且消费者要的「每个任务换一个新 IP」正是时间维度的。
  否决。
- **复用 `/ctl/` 住宅控制面承载普通组的切换。** `/ctl/` 能烧供应商配额、轮换声明会话，
  权限远大于「切一个组的成员」；把普通代理组塞进去会让只想换出口的消费者握着过剩权限。
  否决。
- **给看板 token 也套一层管理员 Session 的 CSRF。** 看板的凭据在 URL 里，浏览器不会
  自动附带；CSRF 保护的是 Cookie 会话，对 URL 凭据不成立。加它只会让 `curl` 与 iframe
  都需要伪造一个无意义的头。否决。

## Consequences

- 看板链接**等同于凭据**。任何拿到它的人都能读拓扑；若 `allow_switch` 打开，还能改出口。
  唯一的吊销路径是停用、换令牌或删除——页面与文档都写明这一点。
- 轮询是本仓库第一个常驻数据面写任务。它已经有界（单组、最小 60 秒、单次写、
  失败隔离），但「控制面主动改数据面运行态」这条先例从此存在；后续若有人想加第二个，
  应当复用这个调度器而不是另起一个 ticker。
- 快照是数据面与 SQLite 的**拼接**，两者之间没有事务。数据面刚重编译完的瞬间可能
  出现「控制面有组、数据面还没有」的窗口，此时该组以 `switchable=false`、`members=[]`
  呈现。这是刻意的：宁可在界面上少显示一个成员，也不假装知道。
- 公开端点多了一个：`/board/` 必须在请求日志里脱敏（已加），且未来若加管理能力，
  必须重新评估它是否该留在公开面。
- `traffic_unavailable`（控制面没装流量采集器）时流量区不可用，但看板其余部分正常。
  这条降级是显式的，不是静默空白。

## Testing

- `internal/board/service_test.go`（21 项）：默认只读与 `all` 范围、非法轮换参数、
  「有策略无间隔」强制归零、空范围不放大成全部、只有 Selector 可切换、
  离线不失败且仍列出组、未授权 token 是 NotFound、切换的四类拒绝、
  `fastest` 忽略死节点、轮换只在间隔到达时推进、版本冲突、换令牌使旧链接失效。
- `internal/api/consumer_board_test.go`（19 项）：公开面免会话可读、token 形状校验、
  未知 token 与停用不可区分、`GET /board/<t>` 只接受 GET、`switch` 只接受 POST 并回显快照、
  只读看板 422、未知子路径 404、管理面会话守卫、未知 JSON 字段 400、
  `/stream` 缺凭据先于缺能力被拒、缺流量采集器 503。
- `web/e2e/board-dialog.mjs`（4 档视口，含 360×520）：断言弹窗遮罩铺满视口、
  顶部不被裁、横向不溢出、输入框可见、滚到底后提交按钮可达。
- `web/e2e/terminal-scroll.mjs`：注入 40 个容器强制溢出，断言存在真正的滚动容器且
  能滚到底、端口单元格不被截断且逐条分行、整页无横向溢出。`web/e2e/board-layout.mjs`
  同理覆盖看板三档视口。
- `internal/store/consumer_board_test.go`（10 项）：token 唯一、停用后不再按 token 解析、
  乐观锁、组范围原子替换、外键拒绝未知组、删除级联、轮换游标累加、轮询 SQL 过滤、版本自增。
- `internal/dataplane/mihomo/runtime_test.go`（5 项）：组与节点分离、**排序稳定**
  （Mihomo 返回 JSON 对象，Go map 迭代顺序随机，不排序会让每次轮询都像发生了变化）、
  缺 `history` 读作「未测速」而非 0ms 成功、未运行时与 socket 不可达都报错、非 200 状态报错。
- 端到端：对运行中的控制面创建看板，用真实 token 拉快照、订阅 SSE、执行一次切换，
  并在浏览器里截图确认看板渲染。
