# Agent Note: 代理服务列表在矮断点锁高时会被压成 0 高

Status: implemented

## Problem

控制面 API 已经有 Listener 和组, 浏览器也打过 `GET /api/v1/listeners`, 但「代理服务」页看起来像没建过: 只剩「服务列表」标题, 没有行。空库时反而正常, 因为空状态写了 `min-h-48`。

页面用 `lg:` (1024px) 把外壳锁成 `h-screen overflow-hidden`, 而列表所在的列要到更宽的断点才有确定的可用高度。介于两者之间是单列, 列表写成 `flex-1 min-h-0`: 父级高度随内容算, 子级 `flex-basis: 0` 且 `min-height: 0`, 最小内容贡献变成 0, 服务行被折叠。侧栏 + Webx 子路径下内容区经常落在这个宽度。

同一个宽度问题还有第二个表现: 断点定低了之后, 那一列根本装不下行的内容。行里要塞下服务名 + 4-5 个徽章 + 地址 + 出站策略 + 操作下拉; `xl` (1280px) 上内容区只有 988px, 一旦再分出一列, 列表只剩 552px, 行内两列固定宽度一扣, 服务名只剩 114px, 徽章溢出到策略列上。这是「太窄」的直接来源。

## Decision

高度锁与列表的可用高度**永远同断点**, 当前是 `2xl:` (1536px)。

低于 `2xl` 走单列: 外壳不锁高, 页面自己滚动, 列表按内容长高, 并保留 `min-h-48` 兜底。`2xl` 之上外壳锁高, 列表才用 `2xl:flex-1 2xl:min-h-0` 在自身盒子内滚动。

列表**独占整行**, 不再与任何常驻面板并排。创建表单是弹窗 (见 .agents/notes/implemented/simplification/2026-09-29-proxy-service-create-dialog.md), 打开时覆盖在页面上, 关闭时列表拿回全部宽度。于是宽度上只剩一个约束 —— 行内容对宽度的硬需求, 由 `truncate` + `shrink-0` 兜底, 不再需要靠"把断点抬高到某一列够用"来间接满足。

断点从 `xl` 抬到 `2xl` 是为了高度锁与列表高度一致, 不是为了腾宽度; 宽度问题已由"不再分列"解决。

约束写在 `routing-page.tsx` 的列表容器和 `App.tsx` 外壳上, 因为把 `min-h-0 flex-1` 看成普通 flex 清理就会回归。

## Alternatives considered

**什么都不做, 让用户把窗口拉宽或点刷新。**

零改动, 而且在足够宽的视口上本来就能显示行。否决: 内容区宽度不由用户控制 (侧栏 + Webx 子路径), 空状态可见、有服务反而消失, 无法从 UI 判断是「没建成功」。

**只给列表加 `min-h-48`, 不改断点。**

能让行重新出现, 改动面最小。否决: 矮断点外壳仍然 `overflow-hidden`, 单列时下方内容会被裁掉, 只是把「看不见服务」换成「看不见别的」。

**把锁高降到 `lg` 对齐。**

断点重新对齐, 锁高路径就能喂给列表一个定高。否决: 1024 宽单列会把名称、策略、操作挤爆, 而 `xl` 实测也不够。

**只把行内容压缩 (更小字号、更短文案) 以适应窄列。**

不动布局, 只让内容适应宽度。否决: 徽章和地址是行上仅有的信息载体, 压缩字号是用可读性换不溢出; 而收起后的行本来只有 64px 高, 宽度给够即可一行放下。

## Consequences

- `2xl` 以下的代理服务页走整页滚动, 不再试图在一屏里塞下所有内容。
- `2xl` 及以上外壳锁高, 列表在自身盒子内滚动。
- 列表在任何宽度都独占整行, 行内容不因"挨着别的面板"被压窄。
- App 外壳里 routing 的 `overflow-hidden / h-full` 与页面断点一致地停在 `2xl`; 终端页仍用 `lg`, 互不影响。
- 行的可点击区域与展开默认值见 .agents/notes/implemented/simplification/2026-09-29-routing-rows-start-collapsed.md。
- 创建表单从常驻右栏改为弹窗, 见 .agents/notes/implemented/simplification/2026-09-29-proxy-service-create-dialog.md。
