# Agent Note: 代理服务列表在 lg 锁高、xl 才双栏时会被压成 0 高

Status: implemented

## Problem

控制面 API 已经有 Listener 和组, 浏览器也打过 `GET /api/v1/listeners`, 但「代理服务」页看起来像没建过: 只剩「服务列表」标题, 没有行。空库时反而正常, 因为空状态写了 `min-h-48`。

页面用 `lg:` (1024px) 把外壳锁成 `h-screen overflow-hidden`, 双栏却要到 `xl:` (1280px) 才启用。介于两者之间是单列, 列表写成 `flex-1 min-h-0`: 父级高度随内容算, 子级 `flex-basis: 0` 且 `min-height: 0`, 最小内容贡献变成 0, 服务行被折叠。侧栏 + Webx 子路径下内容区经常落在这个宽度。

## Decision

高度锁和双栏对齐到 `xl:`。低于 `xl` 让页面自己滚动, 列表按内容长高, 并保留 `min-h-48` 兜底。只有真正两列、外壳已锁高时, 列表才用 `xl:flex-1 xl:min-h-0` 在列内滚动。

约束写在 `routing-page.tsx` 列表容器上, 因为把 `min-h-0 flex-1` 看成普通 flex 清理就会回归。

## Alternatives considered

**什么都不做, 让用户把窗口拉到 1280 以上或点刷新。**
零改动, 而且在足够宽的 xl 视口上双栏路径本来就能显示行。否决: 内容区 < 1280 在 Webx 侧栏布局里是常态, 空状态可见、有服务反而消失, 无法从 UI 判断是「没建成功」。

**只给列表加 `min-h-48`, 不改断点。**
能让行重新出现, 改动面最小。否决: `lg` 外壳仍然 `overflow-hidden`, 单列时新建表单在列表下面会被裁掉, 只是把「看不见服务」换成「看不见表单」。

**把双栏也降到 `lg:`。**
断点重新对齐, 锁高路径就能喂给列表一个定高。否决: 1024 宽两列会把名称、策略、操作挤爆, 这正是当初双栏放在 `xl` 的原因。

## Consequences

- `lg` 且非 `xl` 的代理服务页会走整页滚动, 不再试图在一屏里塞列表 + 新建表单。
- `xl` 以上行为保持: 左列列表内滚动, 右列新建表单固定。
- App 外壳里 routing 的 `overflow-hidden / h-full` 从 `lg` 改到 `xl`; 终端页仍用 `lg`, 互不影响。
