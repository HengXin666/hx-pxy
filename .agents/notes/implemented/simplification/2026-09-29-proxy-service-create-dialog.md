# Agent Note: 新建代理服务改为弹窗

Status: implemented

## Problem

「新建代理服务」原本是页面右栏一张常驻表单, 与「服务列表」并排。它有三个代价。

第一, 它把列表挤窄。表单列取 360-420px 下限, 列表列在 1600 视口上只剩 775px; 而服务行要塞下服务名 + 4-5 个徽章 + 地址 + 出站策略 + 操作下拉, 行内两列固定宽度一扣, 服务名被截断、徽章紧贴策略列。列表的宽度需求是刚从「行内容溢出」修出来的 (见 .agents/notes/implemented/bug-fix/2026-09-18-proxy-service-list-collapses.md), 现在又被这张"偶尔用一次"的表单吃掉一块。

第二, 它让整页的布局多出一套断点耦合。列表列宽、表单列宽、高度锁三者必须同断点, 改一个就要重算另外两个。

第三, 它与仓库其他新建入口不一致: 「新建订阅」与「新建住宅渠道」都是弹窗, 只有代理服务是常驻表单。

## Decision

创建表单抽成 `web/src/components/create-proxy-service-form.tsx`, 用 `Dialog` 承载, 由页面顶栏的「新建代理服务」按钮打开; 列表回到单列独占整行。

弹窗形态同时解决了列表宽度与断点耦合: 打开时表单拿到自己的一层, 关闭时列表拿回全部宽度, 两者不再争同一行的水平空间。页面因此只剩一个宽度约束 —— 列表本身对宽度的硬需求, 它由 `truncate` + `shrink-0` 兜底。

按钮放在顶栏右侧, 与「刷新」「重新应用」同组; 空列表时在空状态里再给一个入口, 否则新装用户看到的只有一段说明文字。

顺带把 `strategyChoices` / `listenerKinds` / `regionChoices` / `strategyLabel` / `regionLabel` / `matchesRegion` 从页面与表单各自的副本收进 `web/src/lib/proxy-groups.ts`: 创建表单和列表徽章读的是同一份策略与地区定义。

## Alternatives considered

**什么都不做, 保持右栏常驻表单。**

零改动, 而且常驻表单有一个真实优点: 建完一个可以立刻建下一个, 不用重复打开。否决: 代价落在每次打开这个页面的时候 (列表被压窄、徽章贴边), 而收益只在连续创建时才出现; 服务是低频资源, 连续创建不是主场景。

**保持常驻, 但把表单折叠成一个可展开的窄条。**

平时不占宽度, 需要时展开。否决: 展开后仍要挤占列表宽度, 只是把「一直窄」换成「有时窄」, 断点耦合一个都没少; 而且多一层折叠状态要维护。

**把表单改成独立路由页 (#/routing/new)。**

空间最充裕, 长表单最舒服。否决: 创建是一次性动作, 独立页把「看完列表决定加一个」变成一次跳转 + 返回, 丢掉了列表上下文; 而且它要新增一条路由与页面 chunk, 收益不成比例。

**弹窗但保留右栏, 只把表单换掉。**

改动更小。否决: 右栏留空会变成一块死区, 双栏本身就没有存在理由了。

## Consequences

- 1600 视口下服务列表从 775px 恢复到 1308px; 服务行不再截断服务名、徽章不再贴住策略列。
- 页面在任意宽度都是单列, 不再需要「列表列宽 / 表单列宽 / 高度锁」三者同断点的约束; `2xl` 之上仍保留外壳锁高 + 列表内滚动。
- 创建成功后弹窗自动关闭并刷新列表 (原来的行为: 清空名称、留在原地)。
- 取消 / Esc / 点遮罩都可关闭, 提交中禁用关闭, 避免半途丢状态。
- 顶栏按钮组从 2 个变 3 个, 窄屏下用 `grid-cols-3` 均分。
- 上一轮刚修的服务行宽度问题不会因为"表单搬走、列表变宽"而复现: 行的 `truncate` 与 `shrink-0` 仍在原处。
