# Agent Note: 代理服务列表默认折叠

Status: implemented

## Problem

代理服务列表的每一行首次进入时全部自动展开, 于是七个服务各带一份完整的「节点成员」表, 页面只能看到第一个服务的前十几个节点。要看清单里有哪些服务、它们各自通不通, 得先把每一行逐个收起来。

被取代的旧决策 (.agents/notes/archived/bug-fix/2026-09-18-routing-members-collapsed.md) 解决的是另一个问题: 当时折叠行只剩服务名和一个 `29/41 可用` 徽章, 看起来像「没节点」。但现在行头已经带上了徽章、地址、出站策略和操作下拉, 「这个服务有几个成员、几个可用」在折叠态就能读到, 展开不再是获取该信息的唯一途径。

## Decision

`web/src/pages/routing-page.tsx` 的 `expanded` 初值保持空 Set, 不再在加载后把全部可见 Listener 填进去。展开有三条入口: 点整行、点行首箭头、或打开「编辑服务」(编辑会自动展开该行)。展开状态不再被加载重置 —— 用户收起后刷新仍是收起的。

同时把该行的可点击区域做成可达的控件: 行头是 `role="button"` + `tabIndex=0` + `aria-expanded`, 回车/空格切换。原先只有那个 7x7 的箭头能展开, 整行虽然绑了 onClick 却是鼠标专用。

## Alternatives considered

**什么都不做, 保持默认展开。**

零改动, 且旧 note 论证过它挡住的那个误判 (「看不到节点」会被读成库存空或建组失败)。否决: 那个论据在当前行头下已经失效 —— 健康数徽章就在折叠行上; 而代价是每条服务都把后面的服务顶出首屏, 列表越长越糟。

**默认展开但只展开第一个服务。**

首屏仍能看到一份成员表, 其余收起来。否决: 「第一个」没有语义, 排序变了就换人, 是个会随数据漂移的隐性规则; 要么都展开要么都收起才可预测。

**默认折叠, 但用 localStorage 记住每一行的展开状态。**

刷新后回到用户离开时的样子。否决: 服务器与订阅会增删, 存下来的行 id 会指向不存在的行, 需要一套失效清理; 对一个默认收起的列表, 持久化的收益抵不上这份复杂度。

**保留旧的 `expanded` 自动填充, 只把断点/宽度调好。**

只管视觉, 不动交互。否决: 用户这次同时提了「不要默认展开」, 展开是独立于宽度的诉求。

## Consequences

- 打开 `#/routing` 时七个服务各占一行, 一屏能看全。
- 成员表、流量、路由策略、实时日志仍在同一行内一键展开, 能力没有减少。
- 键盘用户首次可以用回车/空格展开行 (此前只能 Tab 到箭头按钮)。
- 旧 note 已归档 (.agents/notes/archived/bug-fix/2026-09-18-routing-members-collapsed.md), 本笔记从它的路径反向引用它; 归档件是封存快照, 不再编辑。
- .agents/notes/implemented/bug-fix/2026-09-18-proxy-service-list-collapses.md 的断点结论仍有效, 这次改动把它的双栏断点从 `xl` 推到 `2xl`, 该篇已就地更新。
